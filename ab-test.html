L1 event-chat classifier: текущий vs AI 2.0 paradigm
создано 17.05.2026 · файл: lcb_classifier.py
Запланирован
Гипотеза: текущий L1 (Sonnet/Gemini batch) выбирает verdict из 7 enum-категорий и часто промахивается на skip — пропускает реальные music_band / broker заявки (видели десятки сегодня). По эталону smart_funnel.L1_SCREEN_PROMPT (тест 6/6 PASS): Gemini лучше работает как бинарный screener (escalate / clear), не как enum-классификатор.

Вариант v1 (текущий)

  • Gemini Flash batch (40 постов в одном промпте)
  • Output: verdict из 7 enum
  • L2 escalation на skip + low confidence (мой коммит 49deea4)

Вариант v2 (AI 2.0 paradigm)

  • Gemini Flash batch — бинарный screener: obvious_skip / needs_deeper
  • При obvious_skip — verdict только skip (без выбора из enum)
  • При needs_deeper — автоматическая эскалация на Opus L2
  • L2 Opus делает финальный verdict из 7 enum (как уже сделано в _classify_one_opus)
Эталон: smart_funnel.L1_SCREEN_PROMPT + test_l1_gemini.py. Memory: feedback_gemini_screener_pattern.md. Идея — Gemini ок для escalate/clear, плохо для multi-enum (путает «Интерес» vs «Холодный ответ»).

[Эталон] Funnel L1 Gemini screener vs Opus full
16.05.2026 · файл: test_l1_gemini.py
Готов / 6/6 PASS
Гипотеза: Gemini Flash может работать как pre-screener для funnel-классификатора (DM-ответы клиентов) — escalate sus cases на Opus, resolve обычные cold-ack.

Результат

  • 6/6 test cases PASS
  • Gemini ок для бинарного escalate/clear
  • Соблюдает forbidden-list (не ставит «Не актуален» / «vendor»)
  • НЕ давать выбирать из enum со многими опциями (путает «Интерес» vs «Холодный ответ»)
Эталон применён в smart_funnel._classify_l1_gemini. Memory: feedback_gemini_screener_pattern.md.

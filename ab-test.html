L1 event-chat classifier: v1 (текущий) vs v2 (Gemini screener + Opus L2)
17.05.2026 · завершён · v1 wins · файл: lcb_classifier.py
Завершён · v1 wins
Итог: v2 (Gemini binary screener + Opus L2) проиграл по всем метрикам против v1 (текущий Sonnet/Gemini batch). На 45-постовом heuristic ground-truth v2 имел false_skip +10pp (хуже основной метрики). На частичном прогоне с Opus-judged 100-постовым gold-set рано подтвердилось: v2 промахивается на false_skip даже с confidence 0.97 (post #6: gt=solo_musician → v2=skip). Решение: остаёмся на v1. v2 архивирован. Weekly auto-run выключен.

Что усвоили (для будущих тестов)

  • Gemini Flash как screener для event-постов недостаточно умный — путает «реклама подрядчика» vs «организатор ищет»
  • Confidence 0.97 не спасает от false_skip — Gemini уверен в неверных кейсах
  • Эталон smart_funnel.L1_SCREEN_PROMPT работает для DM-классификации (DM 6/6 PASS), но event-чат посты сложнее (вне известного контекста)
  • Ground-truth через Opus judge с margin_check работает — 100 items за ~30 мин, $1.5
  • Hard guards в auto-deploy (false_skip ≤ v1, recall ≥ v1) спасли — v2 не выкатился автоматически

Вариант v1 (текущий)

  • Gemini Flash batch (40 постов в одном промпте)
  • Output: verdict из 7 enum
  • L2 escalation на skip + low confidence (мой коммит 49deea4)

Вариант v2 (AI 2.0 paradigm)

  • Gemini Flash batch — бинарный screener: obvious_skip / needs_deeper
  • При obvious_skip — verdict только skip (без выбора из enum)
  • При needs_deeper — автоматическая эскалация на Opus L2
  • L2 Opus делает финальный verdict из 7 enum (как уже сделано в _classify_one_opus)

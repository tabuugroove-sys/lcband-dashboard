↓
  1. Listener ловит событие
    NewMessage(incoming=True, is_private=True) → запускает тред
  2. Картотека обновляется ПЕРВОЙ force=True
    lead_context_enricher.enrich(username, "tg", force=True) — обходит 30-мин freshness check, принудительно включает новое сообщение в карточку. Выполняется синхронно в треде, до запуска агента.
  3. Запуск агента
    unified_dm_responder.handle({channel, username, text, ts})
  4. Агент читает свежую карточку
    get_or_enrich(username, channel) — если карточка устарела (cron-путь) — обновляет; иначе берёт актуальную из кеша
  5. Хард-стоп проверка
    is_refused_any(username) — проверяет ОБА namespace (lcb + broker). Был отказ хоть от одного → стоп, ответ не отправляется
  6. Opus генерирует ответ
    Полный контекст переписки + карточка + текущий текст → claude_cli.call_opus()
    Anti-ban: 8/run · 40/день · jitter 15–35s
  7. Approval gate / auto-send
    Горячие / нестандарт → approval-bot. Холодные ≥2 дней молчания + ai_review=="ok" → авто-отправка
  8. Dual-stream после отправки одновременно
    Поток 1 → сообщение отправлено в DM
    Поток 2 → _record_outgoing_to_cache(out=True) + enrich(force=True) — исходящий текст тоже попадает в картотеку

3
Картотека контекста
lead_context_store.json · два namespace · что пишется · что читается
📘 LCB Картотека
Ключ: tg:username
Namespace: lcb (дефолт)

Хранит:
— История переписки (вх + исх)
— Тип клиента, этап воронки
— Стиль общения (ты/Вы)
— Сигналы интереса / отказа
— Дата события, формат, бюджет

Читает: Agent 2 — unified_dm_responder
📙 Broker Картотека
Ключ: broker:tg:username
Namespace: broker

Хранит:
— История брокер-переговоров
— waiting_for_us / silence_days
— Ценовые ориентиры
— Подрядчики и статусы

Читает: Agent 3 — broker_pipeline
🛑 Общий хард-стоп is_refused_any(username)
Проверяет оба namespace. Если человек отказал LCB или Broker — оба агента замолкают. Один общий регулятор на двух агентов.
Когда обновляется и читается
СобытиеВызовПорядок / условие
ЗАПИСЬ Входящее DM enrich(force=True) Синхронно в listener-треде, до запуска агента
ЗАПИСЬ Исходящее DM _record_outgoing_to_cache() + enrich(force=True) Сразу после успешной отправки (dual-stream)
ЧТЕНИЕ Генерация ответа get_or_enrich(username, channel) Внутри агента, перед каждым Opus-вызовом
ЧТЕНИЕ Follow-up get_or_enrich(username, channel) В tg_followup.py перед каждым драфтом
СТОП Хард-стоп is_refused_any(username) Перед любым ответом (оба агента)
ФОН Фоновый cron enrich_all() attention-auto-action каждые 30 мин — пропускает свежее 30 мин
Файлы:

conversation_cache/<username>.jsonl — TG история (вх + исх)
vk_conversation_cache/<peer>.jsonl · wa_cache/<phone>.jsonl
Запись: {"id": -ts, "date": "...", "out": true/false, "text": "...", "media": false}

Фолоу-апы
Кто, когда и как пишет повторно
АгентРасписаниеТриггерКонтекстВыход
tg_followup.py Ежедневно 10:09 Молчит ≥ 2 дня, статус «Переговоры» / «Follow-up» get_or_enrich() → LCB картотека Opus драфт → approval bot
attention_auto_action.py Каждые 30 мин requires_attention = true в orders.db ai_review_before_send() pre-send check auto-send или pending approval
vk_followup.py По расписанию VK лид без ответа N дней VK conv cache → get_or_enrich() VK DM reply
broker-client-followup По расписанию Broker: клиент молчит N дней get_or_enrich(ns="broker") Broker DM → Opus → approval
broker-contractor-followup По расписанию Подрядчик не ответил Broker картотека DM подрядчику
tg_responder.py WatchPaths + 5 мин safety Новый DM или pending_rerun conv_cache → картотека Ответ в TG DM
Правило авто-отправки: только если клиент молчит ≥ 2 дня И ai_review_before_send() == "ok". На skip / adapt / API down → pending approval, никогда вслепую.

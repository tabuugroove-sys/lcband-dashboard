↓
  1. Listener ловит событие
    NewMessage(incoming=True, is_private=True) → запускает тред. Работает на любой новый private DM, не только первое сообщение.
  2. Входящее фиксируется в cache, потом обновляется картотека force=True
    _record_incoming_to_cache(out=False) → lead_context_enricher.enrich(username, "tg", force=True). Enricher обходит 30-мин freshness check, читает conversation_cache + tg_full_export + live TG fallback. Если клиент ответил хотя бы один раз, минимальная context-card сохраняется до AI. Если known events пустой, но thread явно про одно мероприятие, создаёт event через event_graph.py в orders.db.eg_* и переносит key asks в event-card.
  3. Запуск агента
    unified_dm_responder.handle({channel, username, text, ts})
  4. LCB band-member route
    LAZ/Ира/Стас/Лео/Teddy из tg_whitelist.json идут в band_member_reply.py: только факты по подтверждённым event'ам, performer-safe репертуар и runtime-поиск конкретных файлов в promo-папке; payment/new-gig/personal → silent.
  5. LCB promo material resolver
    lcb_promo_materials.py раскрывает promo-папку Я.Диска и даёт writer'у отдельные ссылки по смыслу запроса: видео, фото/костюмы, райдер/репертуар, LAZ/TEDDY; общая promo-ссылка остаётся fallback.
  6. Агент читает свежую карточку
    get_or_enrich(username, channel) — если карточка устарела (cron-путь) — обновляет; иначе берёт актуальную из кеша
  7. Хард-стоп проверка
    payment/refusal/musician/aggregator regex + context refusal. Payment → alert, refusal/spam/musician → skip, техсигнал → production mode.
  8. Opus генерирует ответ
    Полный контекст переписки + карточка + текущий текст → claude_cli.call_opus()
    Anti-ban: 8/run · 40/день · jitter 15–35s
  9. Routing verdict
    sent → TG/VK direct send; WA → funnel_maintenance.py queues wa_computer_use_queue.json for WhatsApp Desktop path · money → notify bot only · skipped → spam/refusal/musician/unclear · error → log/state consultant gap; no second DM sender
  10. Dual-stream после отправки одновременно
    Поток 1 → сообщение отправлено в DM
    Поток 2 → _record_outgoing_to_cache(out=True) + enrich(force=True) — исходящий текст тоже попадает в картотеку и активный event

LCB read-layer + Broker SSoT · что пишется · что читается
📘 LCB Event SSoT
Файл: lcb_orders.json
Read-layer: lcb_event_context.py

Хранит:
— Event как сущность
— Organizer + performers/tech
— Stage / next_action / waiting flags
— lcb_writer_mode + history, синхронно с CRM funnel stage
— Promises, roles, active_event; тех/contractor dependencies не stale по отсутствию в compact AI output
— Internal subrequests: например DJ или folk cover-band (баян/балалайка/народный элемент) → broker_pipeline для цены/видео/style-match

Обновляют: inbound/outbound context, CRM status/history, event graph owners (orders.db.eg_*)
Читает календарь: /api/event_stubs строит pre-paid заявки напрямую отсюда, без отдельного SQL/date push.
📙 Broker Event SSoT
Файл: broker_orders.json
Read-layer: broker_order_context.py

Хранит:
— Event как сущность
— Organizer + contractors/candidates
— Stage / status / history
— Смысл переговоров, цены, медиа
— Vendor promo/media read-model: broker_vendor_media.json из roster + переписок + broker_promo/

Читает: Broker контур — broker_casting / broker_dialog_agent
🛑 Общий хард-стоп is_refused_any(username)
Читает LCB contact-card как общий contact hard-stop. Broker-specific статус/отказ живёт в broker_orders.json, без второй broker-картотеки.

ЧТЕНИЕ Генерация ответа lcb_event_context.card_by_contact() Read-only карточка из lcb_orders.json перед Opus-вызовом; writer видит subrequests как отдельные зависимости

Broker → contractor сообщения обходят client review и отправляются сразу; broker → client идёт через presend, context и duplicate guard. tg_responder.py hard-disabled для общего DM send; в broker-контуре он только маршрутизирует contractor inbound в broker_dialog_agent.py.
